# Paper 4 release decisions

`lesson-release-decisions.json` is the only editable source for the five review
states copied into the 26 generated `LessonReleaseRecord` entries.

The same file also owns the separate `paper4-readiness-contract-v1` state:

- `release_allowed` means the lesson route may be used for guided revision;
- `topic_ready` means the individual lesson has passed the current topic gates;
- `paper_ready` means the whole course has passed ER0–ER5, including full timed rehearsal.

These fields are deliberately not synonyms. The learner homepage and lesson
headers read them through `app/lib/paper4/readiness.ts`; components must not
hard-code a ready lesson or infer whole-paper readiness from route access.

`content/paper4/teacher/assessment-resolution-bridge.json` is generated by
`npm run generate:paper4:e0-bridge`. It gives all 79 canonical assessment items
a stable learner route and task target, then resolves the remaining syllabus
requirements through the Teacher supplemental crosswalk. A bridged item is not
yet a claim that its full canonical prompt and rubric are rendered. The E0
checker reports the remaining task-metadata debt explicitly.

The E0 follow-up embedded all 44 supplemental crosswalk requirement IDs in the
declared visible projection tasks. The generated bridge must therefore report
`pending_embedded_metadata: 0`; any later omission or path drift fails the E0
contract and the independent technical-surface checker.

A lesson is releasable only when all of these fields are `PASS`:

- `locale_parity`
- `academic_review`
- `execution_review`
- `ux_review`
- `lead_gate`

`release_allowed` must equal that five-field result. It cannot remain `false`
after all five fields pass, and it cannot become `true` while any field is
`FAIL` or `PENDING`.

Every decision field cites one or more entries in `evidence_catalog`. Evidence
entries are locked by SHA-256, identify the review dimension, and state the
outcome they support. The checker rejects missing files, hash drift, mismatched
dimensions, mismatched outcomes, missing or duplicate lessons, generated-record
drift, and early promotion.

To promote a lesson after independent QA R4:

1. Save the final evidence file under the project planning tree.
2. Add an evidence-catalog entry with its relative path, SHA-256, review
   dimension and asserted `PASS` status.
3. Change only the decision fields supported by that evidence.
4. Set `release_allowed` to `true` only when all five fields are `PASS`.
5. Run `npm run generate:paper4:full-registry`.
6. Run `npm run verify:paper4:full-registry`.

The 2026-10-02 remediation closed the academic, execution, UX and Lead gates.
The manifest now records all five dimensions as `PASS` for all 26 lessons,
backed by SHA-256-locked evidence. All 26 lessons are release-allowed; the
generated full and app registries must remain byte-consistent with this source.
